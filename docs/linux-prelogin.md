# Linux 로그인 화면 원격접속

MDesk 시스템 서비스를 설치하고 로그인 화면을 X11로 실행하면, OS에 로그인하지 않은 상태에서 등록 원격자의 계정·연결 암호로 접속한 뒤 Linux 로그인 화면에서 OS 계정과 비밀번호를 입력할 수 있습니다. MDesk 접속 인증과 OS 로그인은 별개입니다.

## 설치 및 기존 등록 정보 이전

Ubuntu/Debian에서는 업데이트된 `.deb`를 설치합니다. 압축 파일만 실행하는 방식에는 부팅 시 서비스 설치가 포함되지 않습니다.

```sh
sudo apt install ./MDesk-<version>-ubuntu24.04-amd64.deb
sudo systemctl enable --now rustdesk
systemctl status rustdesk --no-pager
```

현재 패키지 이름은 `mdesk`, 서비스 이름은 `rustdesk`입니다. 설치 시 서비스가 갱신되며, 실행 중인 이전 버전 UI는 종료하고 새 버전으로 다시 실행합니다.

기존 사용자 등록을 이전하려면 업데이트 후 **기존 등록 정보를 저장했던 Linux 계정으로 한 번 로그인**하고 MDesk의 보안 설정에서 등록 원격자 목록이 보이는지 확인합니다. 실행 중인 사용자 서버도 서비스 설정 연결이 준비되면 자동으로 이전을 시도합니다. 목록을 불러오거나 저장할 때 서비스 오류가 표시되면 서비스를 확인한 후 다시 시도합니다.

등록 정보는 시스템 서비스 계정의 MDesk 설정 폴더에 `MDesk_registered_remote_users.json`으로 저장됩니다. root의 기본 환경에서는 `/root/.config/mdesk/` 아래이며, 실제 위치는 서비스의 설정 경로에 따릅니다. 파일은 `0600` 권한으로 저장되고 연결 암호는 기존 암호화 형식을 유지합니다. 사용자 개인 설정 전체를 공유하지 않습니다.

이제 등록 목록은 **장비 단위**입니다. 첫 이전 이후에는 서비스 목록이 기준이며, 다른 Linux 사용자 프로필의 예전 목록을 자동 병합하지 않습니다. 원격자 추가·변경·삭제는 MDesk 설정에서 수행합니다. 마지막 원격자를 삭제한 빈 목록도 유지하여 예전 설정이 등록 정보를 되살리지 않게 합니다.

## Ubuntu/GDM 로그인 화면을 X11로 설정

현재 빌드는 GDM Wayland 로그인 화면을 제어하지 못합니다. 로그인 후 사용자 세션에서 Xorg를 선택하는 것만으로는 로그인 화면까지 바뀌지 않습니다.

GDM을 사용하는 Ubuntu에서는 `/etc/gdm3/custom.conf`를, 해당 경로 대신 `/etc/gdm/custom.conf`가 있는 배포판에서는 그 파일을 편집합니다.

```ini
[daemon]
WaylandEnable=false
```

이미 있는 `[daemon]` 섹션에서 `WaylandEnable=false` 항목의 주석을 제거하거나 값을 수정한 후 재부팅합니다. 원격 작업 중 디스플레이 관리자를 즉시 재시작하면 세션이 종료되므로 설정 적용을 위한 재부팅은 작업을 마친 뒤 진행합니다. 자동 OS 로그인 설정은 필요하지 않습니다.

이 안내는 GDM과 Xorg가 설치된 환경을 기준으로 합니다. SDDM/LightDM 또는 Xorg를 제공하지 않는 배포판에는 같은 설정 파일을 적용하지 않습니다.

공식 지원 조건: <https://rustdesk.com/docs/en/client/linux/#login-screen>

## 확인 순서

1. 로그인 상태에서 등록된 원격자 계정·연결 암호로 MDesk 접속이 되는지 확인합니다.
2. 재부팅 후 Linux에 직접 로그인하지 않고 동일한 MDesk 장비 ID로 접속합니다.
3. 로그인 화면이 보이면 Linux 계정과 OS 비밀번호를 입력합니다.
4. 사용자 세션 전환 중 서버 프로세스가 재시작될 수 있습니다. 클라이언트의 기존 재연결 동작을 확인하고, 필요한 경우 같은 장비로 다시 연결합니다. 화면 전환이 중단 없이 유지된다고 보장하지 않습니다.
5. 연결 암호를 변경한 뒤 이전 암호는 실패하고 새 암호는 성공하는지, 원격자 삭제 후 로그아웃·재부팅해도 삭제한 등록이 복원되지 않는지 확인합니다. 이때 별도로 켜 둔 고정/일회용 비밀번호와 최근 인증 세션의 재사용을 구분합니다.

오류 조사 시 피원격지 로그의 `[RemoteUser] Linux 서비스의 등록 원격자 정보 조회`, `[AccessAudit]`, `Registered-user` 항목을 확인합니다. 암호나 설정 파일 전체를 공유할 필요는 없습니다.

`1.6.3.554+prelogin.20260927.2`는 세션 전환 시 배포 실행 파일(`rustdesk`)과 표시 이름(`MDesk`)이 달라 이전 서버 정리에서 누락되던 경로를 보완합니다. 등록 목록 조회는 읽기 요청을 우선 사용하며, 등록 서비스 조회 실패는 일반 암호 오류와 구분해 표시합니다. 이 보완판의 대상 장비 반복 오류 해결 여부는 실제 재접속으로 확인해야 합니다.

여러 로그 파일을 단순히 합쳐 마지막 줄만 보면 과거 인증 성공 기록이 섞일 수 있습니다. 문제가 지속되면 실패 직후 재등록하기 전에 보완판과 함께 제공한 `mdesk-session-check.py`를 `sudo python3 ./mdesk-session-check.py`로 실행합니다. 서비스·프로세스·등록 목록 개수/리비전과 시간순 진단 기록을 읽기만 하며 저장된 암호나 암호문은 출력하지 않습니다.

## 구현 범위

- root 서비스의 전용 저장소와 인증된 `_service` IPC로 등록 정보를 읽고 저장합니다.
- 기존 서비스 IPC의 UID·실행 파일 검증을 유지하고, 등록 정보 요청마다 다시 검증합니다. 로그인 화면 계정에는 읽기만 허용합니다.
- 저장 결과를 확인한 뒤 설정 UI에서 성공 처리합니다. 저장 실패 시 화면의 등록 목록을 되돌리고 오류를 표시합니다.
- 기존 원격자 계정 일치 검사와 challenge 기반 암호 검증, 고정/일회용 비밀번호 정책은 유지합니다.
- Wayland 로그인 화면 지원과 자동 OS 로그인은 포함하지 않습니다.

실제 대상 Linux 머신의 재부팅 → 원격 로그인 → 사용자 화면 전환은 별도로 확인해야 합니다.
